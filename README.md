# 在路上

在路上是直式手機網頁原型。信依真實地理距離計算郵寄時間，預設像真正的國際信件，要等好幾天。地圖上看得到目前位置、剩餘距離與預計抵達。還沒有完整帳號：第一次來先設定「我的地區」，存在這台瀏覽器，之後每封信都從那裡寄出。同一台裝置負責寄出與拆信。

## 本機執行

需要 Node.js 18 以上。

```bash
npm install
npm test
npm start
```

瀏覽器打開 [http://localhost:3000](http://localhost:3000)。畫面是直式欄位，手機寬度會滿版。

主路徑：第一次來先設定我的地區 → 抽一位隨機收件人 → 地圖上先看到對方的名字和城市 → 寫信或上傳照片 → 寄出前先看寄件回執，確認這封信不能收回 → 蓋戳、投入郵筒 → 看信鴿沿著一條線飛 → 抵達後拆信。重新整理後，在路上的信仍停在當時的軌跡位置。伺服器重新啟動也一樣，信記在 `data/letters.json`，不是只放在記憶體裡。地區記在這台瀏覽器，不在信件檔裡。

## 換成可玩快

預設是浪漫慢。要在一分鐘內看完寄出、在路上、拆信，用可玩快：

1. 寫信時按「可玩快」。
2. 打開網址時加上 `?pace=playable-fast`，例如 [http://localhost:3000/?pace=playable-fast](http://localhost:3000/?pace=playable-fast)。這個選擇會留在這次瀏覽。
3. 啟動時設定環境變數 `PACE=playable-fast`。請求沒有自訂節奏時，伺服器與畫面都用可玩快，首頁那些一直在跑的示範旅途也一起變快。

```bash
PACE=playable-fast npm start
```

改回浪漫慢：拿掉環境變數，或設 `PACE=romantic-slow`，或網址用 `?pace=romantic-slow`。兩個名字只接受 `romantic-slow` 和 `playable-fast`。

## 部署

這是 Node 伺服器，不是純靜態網站，不能只丟上 GitHub Pages。程序讀 `PORT`，預設聽 `0.0.0.0`。健康檢查是 `GET /api/health`。

公開網址用 [Render](https://render.com) 的免費 Web Service。倉庫根目錄的 `render.yaml` 就是 Blueprint：

1. 把這個倉庫推上 GitHub。
2. 打開 Render → New → Blueprint，選這個倉庫。
3. 確認服務名稱是 `handwritten-letter`、方案是 Free，套用。
4. 部署完成後的網址是 `https://handwritten-letter.onrender.com`。若名稱已被占用，Render 會請你改名，網址變成 `https://<服務名稱>.onrender.com`。

本機用 Docker 也可以：

```bash
docker build -t handwritten-letter .
docker run --rm -p 3000:3000 handwritten-letter
```

要把信留在容器裡，加上 `-v "$(pwd)/data:/app/data"`。

**磁碟：** 信件和信面寫在 `data/`。Render 免費方案的磁碟是暫時的，重新部署會清空；閒置約 15 分鐘服務會休眠，喚醒後本機檔案也不保證還在。這份原型可以接受。若要寄出的信在重新部署後還在，改用付費方案並把 persistent disk 掛到 `data/`。不查航班、也不需要帳號，所以沒有另外接資料庫。

地圖圖磚向 OpenStreetMap 要，部署環境要能連外網。

寄信只有一條路：抽一位隨機收件人。路線和郵寄時間跟著對方住的城市，從你的地區算起。預設是浪漫慢。想很快看完降落，用上面的可玩快。

想清空資料，停掉伺服器後刪除 `data/letters.json` 和 `data/images/`。

## 我的地區

寄出地不在每一封信上選。第一次打開會先問「我的地區」：從名單點一個城市，或在地圖上點，會對到最近的城市。確定之後寫進這台瀏覽器（`localStorage`，鍵名 `on-the-way-sender`）。格式是 `{ version: 1, originId, senderId }`。`senderId` 是這台瀏覽器的寄件人編號，跟地區一起產生。還沒有帳號；以後若有帳號，同一份地區和編號可以改存到帳號上，不再讀這個鍵。

寫信、抽收件人時只把地區當成回郵地址顯示，不能在那裡改。首頁標題旁有一行很小的「地區 · 城市」，那才是設定，跟寄出分開。改地區只影響之後的信，寄件人編號不變。已經寄出的信，寄出地記在那封信上，不會跟著改。

## 同時在路上

同一寄件人編號能同時寄出幾封，看這位已經送達幾封。對照 [Postcrossing 的公開表](https://www.postcrossing.com/help/how-many-postcards-can-i-send)，但最多十封，不再往上。Postcrossing 在送出五十封之後還會每五十封多一格，直到同時一百封；我們停在十封。他們六十天沒被登記就過期；我們的信一定會到，所以沒有過期。

| 已送達 | 可同時在路上 |
| --- | --- |
| 0 到 4 封 | 5 封 |
| 5 到 14 封 | 6 封 |
| 15 到 24 封 | 7 封 |
| 25 到 34 封 | 8 封 |
| 35 到 49 封 | 9 封 |
| 50 封或更多 | 10 封 |

草稿不算。沒有寄件人編號的舊信，不論在路上或已送達，都不算。畫面上的郵票格跟目前的上限一樣多：寄出的那幾格蓋了郵戳，旁邊寫「還可寄 2 封」這類字。還沒到十格時，會寫「再送達 3 封就多一格」這類字。格數滿了就不能再寄，會寫最早的那封何時送到。可玩快用同一張表。

寄出時把寄件人編號交給伺服器，寫在那封信上。超過上限時伺服器拒絕，例如「路上已經有 5 封信。等最早的那封送到，才能再寄。」

這是瀏覽器裡的編號，還沒有帳號。換一台瀏覽器、清掉這個網站的資料，或自己換一個編號，五封的上限就重新算。真正的帳號做出來之前，這個上限擋得住一般使用，擋不住有意避開。

清掉瀏覽器裡這個網站的資料，下次會再問一次地區。只刪 `data/letters.json` 不會忘掉地區。

## 隨機收件人

這是畫面上唯一的寄法。名單裡有 20 位示範收件人，分在亞洲、歐洲、非洲、美洲、大洋洲的真實城市，也是可以選的地區。抽籤在伺服器：避開你的地區所在城市，也避開剛剛抽到、或這台裝置剛寄出的那位。飛行時間用下面的距離公式，從你的地區算到對方住的城市，不另外加速。

抽出之後先停在地圖上，確認名字、城市、那一條線和郵寄時間，再進入寫信。

以前從首頁固定路線寄出、已經寫進 `data/letters.json` 的信，座標和時間都記在那封信上，仍會照原路顯示、照原定時間抵達。那些地標（台北、台北101、台中、高雄、東京）不再出現在畫面上，但伺服器仍認得這些編號，舊草稿也能繼續寄出。直接打開 `#/compose` 或舊的固定路線網址，會回到抽收件人。

## 信鴿

每一封信由一隻信鴿送。地圖上是一條墨線，從你的地區畫到收件人的城市，沿大圓過去。信鴿是一枚洋紅墨的戳，套印略微不準，沿著這條線往前。沒有公路、火車、飛機，也沒有中途轉運。

總時間仍用下面的公式，只看寄出地到收件地的大圓距離。換畫法不改天數。例如台北到紐約仍是大約十天。可玩快也還在，只是同一隻信鴿飛得比較快，方便看完寄出和抵達。

已經寫進信件檔、而且存著好幾段路程的舊信，打開時也畫成這一條線。信鴿的位置是寄出時間到送達時間的比例，不跟著舊的路段走。時間到了仍會抵達。

## 寄出與拆信

按「寄出」不會立刻進郵筒。先出現一張郵局櫃檯的寄件回執：寫明一旦投入郵筒就不能收回、也不能再改，並列出收件人、收件城市、寄自哪裡、預計抵達。要再按「確認寄出」才算寄出；「先不寄」會回到信上。這一步不是再點一次同一個按鈕。

確認之後，才在信面蓋上「已寄出」的戳：墨會暈開，並且略微套印不準。接著信滑進郵筒的投口，筒蓋掀一下又蓋上。畫面再慢慢交到地圖，從寄出地跟著拉遠，不是直接切過去。

抵達後按「拆信」：先看到信封、郵票貼紙和郵戳。撕條拉掉、封口掀開，信才從袋口滑出來。拆開後補一小行：在路上多久、信鴿飛了多遠。飛行中讀信面仍然是 403。

## 正在路上

首頁和飛行畫面會顯示「N 封信正在路上」。數字包含這台伺服器上真實飛行中的信，加上 8 條一直在跑的示範旅途。那些旅途在地圖上是淡點，沒有信面，也沒有內文。

## 飛行時間怎麼算

距離是兩點的大圓距離（haversine，地球半徑 6371.0088 公里）。

浪漫慢（預設 `romantic-slow`）先看這封信屬於哪一種路程，再用距離在那個範圍裡取天數，最後加上一個由起迄座標決定的固定微調。同城大約正負兩小時，其餘大約正負四小時。同一條路線每次一樣，微調也不會把天數推出該種路程的範圍。

| 路程 | 怎麼認定 | 天數 |
| --- | --- | --- |
| 同城 | 少於 80 公里 | 約 1 天。先取 26 小時，距離再往上加，最多再加 2 小時 |
| 國內 | 同一個國家，而且不是同城 | 2 到 3 天。80 公里靠近 2 天多，5000 公里靠近 3 天，中間用距離的對數 |
| 鄰近區域 | 同一個洲、不同國家，而且少於 6000 公里 | 4 到 6 天。例如東亞。300 公里靠近 4 天多，6000 公里靠近 6 天，中間用距離的對數 |
| 跨洲或很遠 | 不同的洲，或同一個洲但達到 6000 公里 | 7 到 14 天 |

跨洲或很遠：

```text
天數 = 夾在 7 與 14 之間（7 + 7 × (距離公里 − 6500) / 12500）
```

6500 公里是 7 天，19000 公里是 14 天，中間是直線。台北到倫敦約 9781 公里，落在 8 到 10 天。

下面是算過微調之後的實際時間。

| 路線 | 距離 | 路程 | 浪漫慢 | 可玩快 |
| --- | ---: | --- | ---: | ---: |
| 台北 → 台北101 | 5.0 公里 | 同城 | 1 天 3 小時 | 27 秒 |
| 台北 → 台中 | 132 公里 | 國內 | 2 天 3 小時 | 2 分 18 秒 |
| 台北 → 高雄 | 296 公里 | 國內 | 2 天 11 小時 | 3 分 27 秒 |
| 紐約 → 洛杉磯 | 3937 公里 | 國內 | 2 天 19 小時 | 12 分 33 秒 |
| 台北 → 香港 | 810 公里 | 鄰近區域 | 4 天 15 小時 | 5 分 42 秒 |
| 台北 → 東京 | 2107 公里 | 鄰近區域 | 5 天 | 9 分 11 秒 |
| 台北 → 新加坡 | 3252 公里 | 鄰近區域 | 5 天 5 小時 | 11 分 24 秒 |
| 台北 → 雪梨 | 7264 公里 | 跨洲 | 7 天 9 小時 | 17 分 3 秒 |
| 台北 → 倫敦 | 9781 公里 | 跨洲 | 8 天 19 小時 | 18 分鐘 |
| 台北 → 紐約 | 12525 公里 | 跨洲 | 10 天 5 小時 | 18 分鐘 |
| 台北 → 里約熱內盧 | 18442 公里 | 跨洲 | 13 天 14 小時 | 18 分鐘 |

台北到倫敦是 8 天 19 小時，整段都由同一隻信鴿飛完。台北到紐約是 10 天 5 小時。時間不因畫法而拆開。

可玩快（`playable-fast`，測試用）：

```text
秒數 = 夾在 25 與 1080 之間（12 × √距離公里）
```

- 下限 25 秒，短途也不會瞬移。
- 同城約數十秒，跨城數分鐘。
- 上限 1080 秒（18 分鐘）。約 8000 公里以上會頂到上限，跨洲落在 10–20 分鐘內。12000 公里就是 18 分鐘。

寄出時後端寫入 `departedAt`、`arrivesAt` 和狀態（`draft` / `in_flight` / `delivered`）。進度只看時間：

```text
進度 = (現在 − 寄出時間) / (送達時間 − 寄出時間)
```

位置是這條大圓上的同一個比例。剩餘距離是整段距離乘上還沒走完的比例。舊信即使存了好幾段路程，也用同一種算法。時間到了，後端把狀態改成 `delivered`。在路上不能讀信面，抵達後才打得開。

畫面上的倒數在一天以上會寫成「還有 8 天 5 小時」，不再堆成一大串分鐘。預計抵達用這台瀏覽器自己的時區，並且帶日期，例如「10月7日 下午3:20」。

## API

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| GET | `/api/recipients` | 隨機收件人名單 |
| POST | `/api/recipients/draw` | 抽一位。可帶 `fromId`、`excludeId` |
| GET | `/api/route?fromId&toId` | 某組起迄的距離、飛行時間與分段 |
| GET | `/api/activity` | 正在路上的信數量，與淡點旅途（不含信面） |
| GET | `/api/letters` | 信件與目前進度 |
| POST | `/api/letters` | 建立。`launch: true` 會直接寄出 |
| PUT | `/api/letters/:id` | 更新草稿 |
| POST | `/api/letters/:id/throw` | 草稿寄出（舊路徑，仍可用） |
| POST | `/api/letters/:id/send` | 草稿寄出，與 `/throw` 同一件事 |
| GET | `/api/letters/:id` | 單封信，含位置與剩餘時間 |
| GET | `/api/letters/:id/image` | 信面。飛行中回 403 |

建立信件的 JSON：

```json
{
  "fromId": "taipei",
  "toId": "ellen",
  "pace": "romantic-slow",
  "imageDataUrl": "data:image/png;base64,...",
  "launch": true
}
```

`fromId` 是這台瀏覽器設定的地區，每一封信帶上同一個寄出地，不是在信上另選的。`toId` 用收件人編號（上面的例子是住在倫敦的 Ellen）。較早的請求若仍帶地標編號，例如 `kaohsiung` 或 `taipei101`，伺服器仍會算出座標，所以已經寫進 `data/letters.json` 的信不受影響。

`pace` 只接受 `romantic-slow` 或 `playable-fast`。沒寫的時候用伺服器預設，也就是浪漫慢；若啟動時設了環境變數 `PACE=playable-fast`，沒寫的請求就改用可玩快。

地圖圖磚是 OpenStreetMap。
