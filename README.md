# 在路上

在路上是直式手機網頁原型。信依真實地理距離計算郵寄時間，預設像真正的國際信件，要等好幾天。地圖上看得到目前位置、剩餘距離與預計抵達。沒有帳號：同一台裝置負責寄出與拆信。

## 本機執行

需要 Node.js 18 以上。

```bash
npm install
npm test
npm start
```

瀏覽器打開 [http://localhost:3000](http://localhost:3000)。畫面是直式欄位，手機寬度會滿版。

主路徑：抽一位隨機收件人 → 地圖上先看到對方的名字和城市 → 寫信或上傳照片 → 寄出 → 看信沿路段上路 → 抵達後拆信。重新整理後，在路上的信仍停在當時的軌跡位置。伺服器重新啟動也一樣，信記在 `data/letters.json`，不是只放在記憶體裡。

## 換成可玩快

預設是浪漫慢。要在一分鐘內看完寄出、在路上、拆信，用可玩快：

1. 寫信時按「可玩快」。
2. 打開網址時加上 `?pace=playable-fast`，例如 [http://localhost:3000/?pace=playable-fast](http://localhost:3000/?pace=playable-fast)。這個選擇會留在這次瀏覽。
3. 啟動時設定環境變數 `PACE=playable-fast`。請求沒有自訂節奏時，伺服器與畫面都用可玩快，首頁那些一直在跑的示範旅途也一起變快。

```bash
PACE=playable-fast npm start
```

改回浪漫慢：拿掉環境變數，或設 `PACE=romantic-slow`，或網址用 `?pace=romantic-slow`。兩個名字只接受 `romantic-slow` 和 `playable-fast`。

## 部署

這是 Node 伺服器，不是純靜態網站，不能只丟上 GitHub Pages。程序讀 `PORT`，預設聽 `0.0.0.0`。健康檢查是 `GET /api/health`。

公開網址用 [Render](https://render.com) 的免費 Web Service。倉庫根目錄的 `render.yaml` 就是 Blueprint：

1. 把這個倉庫推上 GitHub。
2. 打開 Render → New → Blueprint，選這個倉庫。
3. 確認服務名稱是 `handwritten-letter`、方案是 Free，套用。
4. 部署完成後的網址是 `https://handwritten-letter.onrender.com`。若名稱已被占用，Render 會請你改名，網址變成 `https://<服務名稱>.onrender.com`。

本機用 Docker 也可以：

```bash
docker build -t handwritten-letter .
docker run --rm -p 3000:3000 handwritten-letter
```

要把信留在容器裡，加上 `-v "$(pwd)/data:/app/data"`。

**磁碟：** 信件和信面寫在 `data/`。Render 免費方案的磁碟是暫時的，重新部署會清空；閒置約 15 分鐘服務會休眠，喚醒後本機檔案也不保證還在。這份原型可以接受。若要寄出的信在重新部署後還在，改用付費方案並把 persistent disk 掛到 `data/`。不查航班、也不需要帳號，所以沒有另外接資料庫。

地圖圖磚向 OpenStreetMap 要，部署環境要能連外網。

固定路線（台北 → 高雄、台北 → 東京、台北 → 台北101）留在首頁下方。預設是浪漫慢，同城也要大約一天。想很快看完降落，用上面的可玩快。

想清空資料，停掉伺服器後刪除 `data/letters.json` 和 `data/images/`。

## 固定路線

地點用真實座標（台北車站、台北101、高雄市、東京車站，另可選台中車站）。

| 路線 | 距離 | 浪漫慢（預設） | 可玩快 |
| --- | ---: | ---: | ---: |
| 台北 → 台北101 | 5.0 公里 | 1 天 3 小時 | 27 秒 |
| 台北 → 高雄 | 296 公里 | 2 天 11 小時 | 3 分 27 秒 |
| 台北 → 東京 | 2107 公里 | 5 天 | 9 分 11 秒 |

同城大約一天。可玩快仍可在半分鐘內看完這條短途降落。

## 隨機收件人

名單裡有 20 位示範收件人，分在亞洲、歐洲、非洲、美洲、大洋洲的真實城市。抽籤在伺服器：避開寄出地所在城市，也避開剛剛抽到、或這台裝置剛寄出的那位。寄出地預設台北，也可以改成名單上的其他城市。飛行時間仍用上面的距離公式，不另外加速。

抽出之後先停在地圖上，確認名字和城市，再進入寫信。地圖上會先畫出這趟的運送分段。

## 運送分段

整段路程不是一條直線。伺服器用一個簡化的轉運規則排出連續路段，不查真實航班時刻：

- 約 80 公里以內：公路（例如台北 → 台北101）
- 同一個國家、80–700 公里：火車（台北 → 高雄）
- 更遠的國內，或跨國：公路到最近的主要機場 → 飛機到對方機場 → 公路到收件人（台北 → 東京會經過桃園機場和羽田機場）

總時間仍用下面的公式，依寄出地到收件地的大圓距離計算。浪漫慢再把這段時間拆開：公路和火車（收件、分揀、轉運、最後一程）的權重是 6，飛機是 1。三段路時，飛機大約是總時間的十三分之一，短於兩邊在機場的停留。不查班表。可玩快仍把大部分時間放在最長的那段，短的公路或火車至少留一點，換交通工具時看得到。

地圖上公路、火車、飛機用不同顏色。飛行中會標出現在是哪一種：公路是貨車，火車是車廂，飛機路段是飛機輪廓。進度一樣只看時間，位置沿著目前這段路往前，不會瞬移。

跨過路段時會停一拍：例如「正在桃園機場轉運，改搭飛機」、「正在羽田機場轉運，改走公路」。底下的句子也跟著路走（「公路上，送往桃園機場」、「飛機上，前往羽田機場」、「最後一段公路，送往東京」），不是只顯示百分比。時間公式不變，這一拍只是畫面上的標示。

## 寄出與拆信

寄出之後，先在信面蓋上「已寄出」的戳：墨會暈開，並且略微套印不準。接著信滑進郵筒的投口，筒蓋掀一下又蓋上。畫面再慢慢交到地圖，從寄出地跟著拉遠，不是直接切過去。

抵達後按「拆信」：先看到信封、郵票貼紙和郵戳。撕條拉掉、封口掀開，信才從袋口滑出來。拆開後補一小行：在路上多久、距離、中途轉了幾次。飛行中讀信面仍然是 403。

換路段時蓋上一張轉運貼紙。它和信封上的郵票是同一套東西：奶油紙、洋紅墨、齒孔虛線、銷戳波浪線。只標轉運，不查班表。

## 正在路上

首頁和飛行畫面會顯示「N 封信正在路上」。數字包含這台伺服器上真實飛行中的信，加上 8 條一直在跑的示範旅途。那些旅途在地圖上是淡點，沒有信面，也沒有內文。

## 飛行時間怎麼算

距離是兩點的大圓距離（haversine，地球半徑 6371.0088 公里）。

浪漫慢（預設 `romantic-slow`）先看這封信屬於哪一種路程，再用距離在那個範圍裡取天數，最後加上一個由起迄座標決定的固定微調。同城大約正負兩小時，其餘大約正負四小時。同一條路線每次一樣，微調也不會把天數推出該種路程的範圍。

| 路程 | 怎麼認定 | 天數 |
| --- | --- | --- |
| 同城 | 少於 80 公里 | 約 1 天。先取 26 小時，距離再往上加，最多再加 2 小時 |
| 國內 | 同一個國家，而且不是同城 | 2 到 3 天。80 公里靠近 2 天多，5000 公里靠近 3 天，中間用距離的對數 |
| 鄰近區域 | 同一個洲、不同國家，而且少於 6000 公里 | 4 到 6 天。例如東亞。300 公里靠近 4 天多，6000 公里靠近 6 天，中間用距離的對數 |
| 跨洲或很遠 | 不同的洲，或同一個洲但達到 6000 公里 | 7 到 14 天 |

跨洲或很遠：

```text
天數 = 夾在 7 與 14 之間（7 + 7 × (距離公里 − 6500) / 12500）
```

6500 公里是 7 天，19000 公里是 14 天，中間是直線。台北到倫敦約 9781 公里，落在 8 到 10 天。

下面是算過微調之後的實際時間。

| 路線 | 距離 | 路程 | 浪漫慢 | 可玩快 |
| --- | ---: | --- | ---: | ---: |
| 台北 → 台北101 | 5.0 公里 | 同城 | 1 天 3 小時 | 27 秒 |
| 台北 → 台中 | 132 公里 | 國內 | 2 天 3 小時 | 2 分 18 秒 |
| 台北 → 高雄 | 296 公里 | 國內 | 2 天 11 小時 | 3 分 27 秒 |
| 紐約 → 洛杉磯 | 3937 公里 | 國內 | 2 天 19 小時 | 12 分 33 秒 |
| 台北 → 香港 | 810 公里 | 鄰近區域 | 4 天 15 小時 | 5 分 42 秒 |
| 台北 → 東京 | 2107 公里 | 鄰近區域 | 5 天 | 9 分 11 秒 |
| 台北 → 新加坡 | 3252 公里 | 鄰近區域 | 5 天 5 小時 | 11 分 24 秒 |
| 台北 → 雪梨 | 7264 公里 | 跨洲 | 7 天 9 小時 | 17 分 3 秒 |
| 台北 → 倫敦 | 9781 公里 | 跨洲 | 8 天 19 小時 | 18 分鐘 |
| 台北 → 紐約 | 12525 公里 | 跨洲 | 10 天 5 小時 | 18 分鐘 |
| 台北 → 里約熱內盧 | 18442 公里 | 跨洲 | 13 天 14 小時 | 18 分鐘 |

台北到倫敦的 8 天 19 小時拆成：公路到桃園機場 4 天 1 小時、飛機到希斯洛機場 16 小時 16 分、公路到倫敦 4 天 1 小時。飛機短於兩邊的停留。

可玩快（`playable-fast`，測試用）：

```text
秒數 = 夾在 25 與 1080 之間（12 × √距離公里）
```

- 下限 25 秒，短途也不會瞬移。
- 同城約數十秒，跨城數分鐘。
- 上限 1080 秒（18 分鐘）。約 8000 公里以上會頂到上限，跨洲落在 10–20 分鐘內。12000 公里就是 18 分鐘。

寄出時後端寫入 `departedAt`、`arrivesAt` 和狀態（`draft` / `in_flight` / `delivered`）。進度只看時間：

```text
進度 = (現在 − 寄出時間) / (送達時間 − 寄出時間)
```

有運送分段時，位置是「目前這段路」上的插值，剩餘距離是後面各段加起來。沒有分段的舊資料仍沿整段大圓前進。多日的信也是用同一段寄出時間和送達時間算進度，不會因為過了一天才跳錯路段。時間到了，後端把狀態改成 `delivered`。在路上不能讀信面，抵達後才打得開。

畫面上的倒數在一天以上會寫成「還有 8 天 5 小時」，不再堆成一大串分鐘。預計抵達用這台瀏覽器自己的時區，並且帶日期，例如「10月7日 下午3:20」。

## API

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| GET | `/api/places` | 固定路線用地點 |
| GET | `/api/presets` | 固定路線 |
| GET | `/api/recipients` | 隨機收件人名單 |
| POST | `/api/recipients/draw` | 抽一位。可帶 `fromId`、`excludeId` |
| GET | `/api/route?fromId&toId` | 某組起迄的距離、飛行時間與分段 |
| GET | `/api/activity` | 正在路上的信數量，與淡點旅途（不含信面） |
| GET | `/api/letters` | 信件與目前進度 |
| POST | `/api/letters` | 建立。`launch: true` 會直接寄出 |
| PUT | `/api/letters/:id` | 更新草稿 |
| POST | `/api/letters/:id/throw` | 草稿寄出（舊路徑，仍可用） |
| POST | `/api/letters/:id/send` | 草稿寄出，與 `/throw` 同一件事 |
| GET | `/api/letters/:id` | 單封信，含位置與剩餘時間 |
| GET | `/api/letters/:id/image` | 信面。飛行中回 403 |

建立信件的 JSON：

```json
{
  "fromId": "taipei",
  "toId": "kaohsiung",
  "pace": "romantic-slow",
  "imageDataUrl": "data:image/png;base64,...",
  "launch": true
}
```

`pace` 只接受 `romantic-slow` 或 `playable-fast`。沒寫的時候用伺服器預設，也就是浪漫慢；若啟動時設了 `PACE=playable-fast`，沒寫的請求就改用可玩快。

地圖圖磚是 OpenStreetMap。
